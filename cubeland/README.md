# Cubeland

A first-person block-building sandbox for 12d Model, drawn entirely in a
`Draw_Box` with polygons.

## Running it

1. Compile `cubeland.4dm` with the 12d macro compiler. It pulls in everything
   else through `src/build.4dm`.
2. Run the compiled `cubeland.4do`.
3. The **Cubeland - worlds** panel opens. Type a world name and, optionally, a
   seed, then press **Create new world**. You can also pick a saved world and
   press **Play selected**.
4. Click the game view to start playing. Press **H** at any time for the
   controls.

Worlds are saved in a `cubeland_worlds` folder inside the 12d working folder.
A world is saved when you quit to the menu, when you press **Save**, and every
two minutes while you play.

## Controls

| Input         | Action                                                       |
|---------------|--------------------------------------------------------------|
| Click view    | start playing (the mouse then turns the camera)              |
| Mouse         | look around                                                  |
| Left click    | break blocks (harder blocks take more hits), hit cows        |
| Right click   | place blocks, eat food, open crafting tables and furnaces    |
| W A S D       | walk                                                         |
| Space         | jump, swim up                                                |
| 1 - 9         | choose a hotbar slot                                         |
| E             | inventory and hand crafting (E or Q closes any screen)       |
| Q             | pause and free the mouse                                     |
| F / J         | auto-walk on/off, auto-jump on/off                           |
| - / =         | shorter / longer view distance (also changes texture detail) |
| I / H         | position and render statistics, help                         |

The keys go to the **Keys** box under the view. If they stop working, click
that box.

12d only sends auto-repeat for the last key held and never reports a key being
released. Because of that, only one movement key works at a time. Each press
moves you for a moment and holding the key keeps you moving. Space keeps your
current movement going so you can run and jump, and auto-jump (on by default)
hops up one-block steps for you.

## What's in it

- **Blocks:** dirt, grass, stone, cobblestone, sand, oak log, leaves, oak
  planks, water, bedrock, crafting table and furnace. Each has its own 16×16
  pixel texture, generated by the macro when it starts.
- **Terrain:** generated from the seed, with hills, mountains, forests,
  beaches and oceans. Water fills every open cell below y 62.
- **Player:** 1.8 blocks tall, with 5 blocks of reach, gravity and collision,
  swimming, fall damage, a 20-point health bar and slow healing.
- **Breaking and placing:** broken blocks drop as items that are picked up
  when you walk near them. Furnaces turn to face you when placed.
- **Inventory:** a 9-slot hotbar and a 27-slot (9×3) inventory. Click to pick
  up, drop or swap a stack. Right-click to split a stack or place one item.
- **Crafting:** a recipe list. Click a recipe to make it. Recipes marked as
  needing a table only appear at a crafting table.
  - 1 oak log → 4 planks (by hand)
  - 2 planks → 4 sticks (by hand)
  - 4 planks → crafting table (by hand)
  - 8 cobblestone → furnace (table)
  - 4 leaves → 2 sticks (table)
  - 1 dirt + 1 leaves → grass block (table)
- **Furnace:** has input, fuel and output slots, and cooks beef or bakes
  cobblestone into stone. Wood is the fuel: logs, planks, sticks and crafting
  tables burn. It keeps cooking while you are in a menu or paused.
- **Cows:** they wander the grassland and avoid cliffs and water. They run
  when hit and drop 1–3 raw beef. Raw beef heals 2 and cooked beef heals 7.

## Code layout

```
cubeland.4dm          main(): world menu, then the game, until Quit
src/build.4dm         includes every source file (in any order)
include/*.h           constants, global data and prototypes per module
src/
  util, events        helpers and the game event queue
  blocks, textures    block/item rules and the procedural textures
  world, mesh         block grid, terrain generator, cached visible faces
  physics, player     collision, ray casting, movement and actions
  inventory, crafting, furnace, cows, drops
  render_world        the 3D view
  render_hud          crosshair, hotbar, health, hand, help, item icons
  render_ui           inventory, crafting table and furnace screens
  save                world files
  game                starting worlds, per-frame update, event dispatch
  menu_panel          world menu panel (controller)
  game_panel          game panel: mouse capture, keys, frame loop (controller)
tools/test_harness/   runs the macro as C++ for testing (not used by 12d)
```

The code follows model–view–controller. The model modules (world, player,
cows and so on) never call each other to report what happened. They emit an
event (`include/events.h`), and `game_dispatch_events()` passes each event to
every module's `*_on_event()` handler. For example, breaking a block emits
`EVT_BLOCK_BROKEN`. The mesh module then rebuilds the nearby faces, the drops
module spawns the item, the save module records the change, and the furnace
module drops a broken furnace's contents.

### Rendering

- The world is cut into 16×16×16 sections. Each section caches the block faces
  that touch air, grouped by direction, so a frame only walks those lists.
  Whole groups facing away from the camera are skipped.
- Faces are projected through a pinhole camera and painted far to near. For
  unit cubes on a grid, ordering by each cube's centre distance is a valid
  back-to-front order, so a bucket sort is enough.
- Each texture is stored as a base colour plus merged rectangles of its other
  colours. Close faces get every rectangle, mid-range faces only the larger
  ones, and distant faces a single average colour. Colours are shaded by face
  direction and fade into the sky with distance.

### Tuning

`include/config.h` holds the world size, physics and entity limits.
`render_set_detail()` in `src/render_world.4dm` holds the three detail levels
(view distance and texture distances). Array sizes must be plain numbers, so
when you change the world size, also update the products written next to it
(`WORLD_CELLS`, `WORLD_COLUMNS`, the strides, the section counts and
`FACE_POOL_SIZE`).

## Testing note

This was written without access to 12d Model. To check it, the macro was
translated into C++ and run against stand-ins for the 12d calls it uses
(panels, `Draw_Box` drawing, files, events). That harness is in
`tools/test_harness`, and its README explains how to use it. It covered world generation,
movement, breaking and placing, crafting, cooking, cows, fall damage, death
and respawn, and saving and loading, with the frames rendered to images. The
code sticks to the language features and library calls the 12dOOM macro
uses.

Two things could not be checked:

- **Frame rate in 12d.** A frame runs about 250,000 statements. That estimates
  roughly 25–30 frames per second at the default view, based on the 12dOOM
  timings. If it's slow, press `-` for a shorter view.
- **The 1.5-million-cell world array.** If 12d refuses an array that large,
  reduce `WORLD_SIZE_X`/`WORLD_SIZE_Z` in `include/config.h`.
